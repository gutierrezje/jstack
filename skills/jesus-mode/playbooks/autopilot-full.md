# Autopilot full

1. Confirm explicit authority for creating, updating, and merging the exact PR queue. Items the operator names as theirs and PRs outside the queue stop at merge-ready. A request to state the plan is not a go.
2. Assign one owner per independent PR with isolated branch/worktree scope and full build-to-green responsibility. Run owners in parallel off trunk and never stack them. Each owner opens its PR early per [$open-pr](../../open-pr/SKILL.md), reports a code-ready head after cleanup and a rebase onto current trunk, pushes after each verified unit, and force-pushes only its own branch with a lease. Keep fix rounds on that base unless trunk conflicts, breaks CI, or lands a concurrent change to the same files.
3. Run owners in bounded parallel waves; serialize overlapping files and dependent work.
4. Run the full independent lanes (gates, real-surface behavior, diff/receipt audit) once, at the code-ready head. Repeat them only for new behavior, a redesign, or a large new diff; a rebase, conflict resolution, or minor fix gets one verifier at the new head, and a wording-only change gets none. Block a PR only for a problem you can show: a failing run at the head, a bug a user would hit, or a wrong shipped doc. A problem the PR's base already has does not block unless the PR copies or newly reaches it. Everything else becomes a follow-up.
5. Return findings to the owner. A verdict covers one patch and green CI covers one head: compare `git patch-id` at the verdict SHA with the current head, keep the verdict when the patch is unchanged, and require fresh CI on every new head. Merge only after a clean root verdict. Right before merging, fetch trunk and rebase only when its changes could affect the patch (a conflict, a file both sides changed, or a change to which checks run); otherwise run the patch's checks on the merge result or merge. Hold and report if trunk would force a third rebase. Anything that loosens a gate, such as a raised budget or allowlist entry, needs verifier proof and the root's fresh countersign; a disabled or soft-failed check comes out. Never bypass an approval the forge enforces.
6. At each audit, re-read this playbook from the current trunk when available and the durable program plan. Judge progress by observable state changes such as commits, pushed heads, PR or check deltas, and evidence receipts. Probe every agent down to the leaf lanes by its side effects, not status text. Inspect any lane that exceeds its expected runtime without one; interrupt and replace it when it is stuck, but answer an agent that is waiting on you instead of replacing it.
7. Use bounded waits while the task is active. Create a heartbeat only when the user explicitly requested recurring monitoring. Keep the decision trail current across every audit. On the operator's stop, every owner takes a zero-writes hold, reports where it stands, and keeps its brief until released.

Reply: catch the operator up per [$ketchup](../../ketchup/SKILL.md) on each PR's state and verdict, what merged, countersigns, open operator gates, and parked follow-ups, with links.

Completion: every authorized PR is merged at a verified SHA or stopped with a documented gate.
